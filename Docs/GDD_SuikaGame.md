# 수박 게임 (Suika Game) — Game Design Document

> **버전**: v1.0
> **작성일**: 2026-05-12
> **타겟 엔진**: Unity 6.3
> **개발 형태**: 1인 클라이언트 개발 프로젝트
> **장르**: 2D 물리 기반 머지 퍼즐 (Physics Merge Puzzle)

---

## 1. 게임 개요 (Overview)

### 1.1 한 줄 요약
> **"같은 과일끼리 합쳐 더 큰 과일을 만들고, 최종적으로 수박을 만드는 2D 물리 퍼즐 게임."**

### 1.2 레퍼런스
- 원작: **Suika Game / スイカゲーム** (Aladdin X, 2021)
- 계보: 중국 모바일 웹게임 *合成大西瓜*(2021) → 일본·전 세계 확산
- 유사 장르: 2048, Threes!, Drop7 의 머지 메커닉을 물리 시뮬레이션으로 재해석

### 1.3 코어 루프 (Core Loop)
```
[조준] → [낙하] → [충돌·낙하] → [같은 등급 충돌 시 합체(머지)] → [점수 획득]
   ↑                                                          ↓
   └────────── [다음 과일 미리보기] ←─── [필드에 누적] ──────┘
                            ↓
                  [데드라인 초과 → GameOver]
```

1. 화면 상단에서 좌우로 이동하며 **현재 과일**을 조준
2. 탭/클릭으로 **드롭(낙하)**
3. 물리 시뮬레이션으로 떨어진 과일이 컨테이너에 쌓임
4. **같은 등급의 과일 두 개가 충돌**하면 **한 단계 위 과일**로 머지 + 점수 획득
5. 머지 결과로 연쇄 반응(체인) 가능
6. 과일이 데드라인 위에 일정 시간 머무르면 **게임 오버**
7. 최종 목표: **수박(11단계)** 만들기 → 가능하면 수박 두 개로 추가 머지 보너스

### 1.4 플랫폼 / 입력
- **1차 타겟**: PC (마우스) / 모바일 (터치)
- **입력 방식**:
  - 좌우 이동: 마우스 X 좌표 추적 또는 터치 드래그
  - 드롭: 좌클릭 / 탭
  - (옵션) 키보드: ← → 이동, Space 드롭

## 2. 핵심 메커닉 (Core Mechanics)

### 2.1 떨어뜨리기 (Drop)
- 플레이어는 컨테이너 **상단 가로 라인**을 따라 좌우로 과일을 움직임
- 과일은 컨테이너 좌/우 벽에 닿지 않게 클램프(clamp)됨
- **드롭 쿨다운**: 0.5~0.7초 (연사 방지, 텐션 유지)
- 드롭 직후 새로운 과일이 슬롯에 스폰
- **다음 과일 미리보기(Next)** UI에 다다음 과일 노출

### 2.2 충돌 (Collision)
- Unity **2D Physics(Rigidbody2D + CircleCollider2D)** 기반
- 모든 과일은 원형 콜라이더로 단순화
- 중력: 표준 9.81 × 스케일 계수 (튜닝 가능)
- **물리 머티리얼(Bounciness)**:
  - 반발력: 0.0 ~ 0.1 (튕김 최소화, 안정적 적층)
  - 마찰: 0.3 ~ 0.5 (자연스러운 굴림)
- **충돌 레이어**:
  - Fruit, Wall, DeadLine, Spawner

### 2.3 합치기 (Merge)
- **조건**: 같은 등급(level) 과일 2개가 충돌
- **결과**:
  - 두 과일 제거
  - 두 충돌 지점의 **중간 좌표**에 한 단계 위 과일 스폰
  - 새 과일은 살짝의 **상승 임펄스(Impulse)** 부여 → 자연스러운 연쇄 유도
  - 머지 이펙트(파티클, 사운드, 가벼운 카메라 셰이크)
- **연쇄(Chain) 처리**:
  - 한 프레임에 다수 머지 발생 가능 → 큐 기반 처리
  - 동시 충돌은 한 쌍만 머지하도록 락(lock) 처리 (중복 머지 방지)
- **최종 단계(수박)**:
  - 수박 두 개 충돌 시 → **둘 다 제거 + 큰 보너스 점수 + 이펙트**
  - 또는 그대로 유지(원작 거의 동일 동작) — 본 게임은 **둘 다 제거** 방식 채택

### 2.4 게임 오버 (Game Over)
- 컨테이너 상단 근처에 **데드라인(Death Line)** 존재
- **판정 규칙**:
  - 과일의 **콜라이더 최상단**이 데드라인을 **연속 2.0초 이상** 초과하면 게임오버
  - 단, **드롭 중**(공중 낙하 상태)인 과일은 판정 제외
  - 데드라인 근접 시 **경고 시각화**(라인 깜빡임, 사운드)
- 게임 오버 시:
  - 모든 물리 정지
  - 점수/하이스코어 비교 및 갱신
  - 결과 화면 표시 (재시작 / 메인메뉴)

## 3. 과일 단계 (Fruit Tiers)

총 **11단계**. 원작과 동일한 진화 체인.

| Lv | 한글명 | 영문명 | 상대 크기(지름) | 머지 점수 | 색상 (참고) |
|----|--------|--------|----------------|-----------|------------|
| 1  | 체리   | Cherry | 1.00 (≈ 40px)  | 1         | 진한 빨강 |
| 2  | 딸기   | Strawberry | 1.25       | 3         | 선명한 빨강 |
| 3  | 포도   | Grape | 1.55           | 6         | 보라 |
| 4  | 데코폰 | Dekopon | 1.95         | 10        | 주황 |
| 5  | 감     | Persimmon | 2.40       | 15        | 진한 주황 |
| 6  | 사과   | Apple | 2.95           | 21        | 빨강 |
| 7  | 배     | Pear | 3.60            | 28        | 연노랑/연두 |
| 8  | 복숭아 | Peach | 4.35           | 36        | 분홍 |
| 9  | 파인애플 | Pineapple | 5.20      | 45        | 황금 노랑 |
| 10 | 멜론   | Melon | 6.20           | 55        | 연두 |
| 11 | 수박   | Watermelon | 7.40       | 66        | 진한 초록 |

### 3.1 크기 규칙
- 등급당 약 **1.18~1.25배** 점진적 증가
- 컨테이너 폭 대비 수박이 약 **55~60%**를 차지하도록 비율 조정
- 콜라이더 반지름 = 시각 스프라이트 반지름과 일치 (시각/물리 일치성)

### 3.2 스폰 규칙
- **드롭 가능 과일**: Lv 1 ~ Lv 5 (체리 ~ 감)
  - Lv 6 이상은 오직 머지로만 등장
- **랜덤 가중치(예시)**:
  - Lv 1: 35%, Lv 2: 30%, Lv 3: 20%, Lv 4: 10%, Lv 5: 5%
- 초반 5초간은 **Lv 1~2만 등장**(부드러운 시작)

### 3.3 점수 공식
- 머지 시 획득 점수 = `n × (n+1) / 2` (n = 새로 생성된 과일의 등급)
- 예: 체리→딸기 머지(n=2) = 3점, 수박 완성(n=11) = 66점

## 4. 점수 · 승패 규칙 (Scoring & Win/Lose)

### 4.1 점수 시스템
- **누적 점수(Score)**: 머지 시마다 가산
- **하이스코어(High Score)**: 로컬 저장 (PlayerPrefs)
- **체인 보너스(선택 사항)**:
  - 1회 드롭으로 연쇄 머지 발생 시 보너스 (×1.2, ×1.5, ×2.0 …)
- **수박 보너스**:
  - 첫 수박 생성: +100 추가 점수
  - 수박+수박 머지: +500 추가 점수 + 화면 연출

### 4.2 승리 / 패배
- **명시적 "승리" 조건은 없음** (엔드리스 스코어 어택)
- **패배(Game Over)**: 데드라인 초과 (2.3 항목 참고)
- **소프트 골(Soft Goal)**: 수박 만들기 = 1차 목표
- **장기 골**: 하이스코어 갱신

### 4.3 실패 후 흐름
- 결과 화면: 최종 점수 / 하이스코어 / 만든 가장 큰 과일
- 버튼: **재도전 / 메인 메뉴 / (옵션) 공유**

## 5. 화면 · UI 구성 (Screens & UI)

### 5.1 화면 구성 (인게임)
```
┌─────────────────────────────────────────┐
│  [Score: 1234]            [Best: 5678]  │ ← 상단 HUD
│                                          │
│       🍒  ← 현재 드롭 과일 (조준)         │ ← 드롭 슬롯
│  ┌────────────────────────────┐          │
│  │   ··········(데드라인)··········│         │ ← 경고선
│  │                              │          │
│  │                              │          │
│  │       (물리 컨테이너)         │          │ ← 플레이 필드
│  │     🍇  🍓   🍎             │          │
│  │   🍒  🍑  🍒  🍇            │          │
│  └────────────────────────────┘          │
│                                          │
│  [Next: 🍓]   [Pause ⏸]                  │ ← 하단 HUD
└─────────────────────────────────────────┘
```

### 5.2 UI 요소 정의
| 요소 | 위치 | 역할 |
|------|------|------|
| Score | 좌상단 | 현재 점수, 머지 시 카운트업 애니메이션 |
| High Score | 우상단 | 베스트 기록 |
| Drop Slot | 상단 중앙 | 현재 드롭할 과일 표시 + 조준선(옵션) |
| Death Line | 상단 안쪽 | 점선/실선, 위협 시 빨강 점멸 |
| Container | 중앙 | 좌·우·바닥 벽, 안쪽이 플레이 영역 |
| Next Preview | 좌하단(또는 우상단) | 다음 과일 미리보기 |
| Pause | 우하단 | 일시정지 |
| Evolution Guide | 사이드 패널(옵션) | 11단계 진화 트리 표시 |

### 5.3 화면 흐름 (Screen Flow)
```
[타이틀] → [메인 메뉴] → [인게임] ⇄ [일시정지]
                            ↓
                       [게임 오버 결과]
                            ↓
                     [메인 메뉴 / 재시작]
```

## 6. 톤 & 분위기 (Tone & Mood)

### 6.1 전반적 인상
- **부드럽고 귀여운 (Cute & Cozy)**
- **포근한 카페/주방 같은 따뜻함**
- **느긋한 캐주얼 게임** — 짧은 세션, 부담 없음

### 6.2 컬러 팔레트
- **배경**: 크림 베이지 (#FBF3E2) / 연한 우디 톤 (#E8D5B7)
- **컨테이너**: 따뜻한 갈색 (#A0724A) — 나무 그릇 느낌
- **데드라인**: 연한 빨강 (#E07A5F) — 평소엔 점선, 위협 시 점멸
- **과일**: 채도 높지 않은 **파스텔 톤** + 부드러운 외곽선
- **UI**: 둥근 모서리(rounded corner), 가벼운 그림자

### 6.3 아트 방향
- 2D 벡터/일러스트 스타일, **둥글둥글한 실루엣**
- 외곽선 살짝 있는 친근한 룩 (스튜디오 지브리 + 일본 모바일 캐주얼 톤)
- 머지 시 **반짝임 파티클 + 가벼운 바운스**
- 카메라 셰이크는 최소 (가벼운 머지엔 무, 수박 머지에만 강하게)

### 6.4 사운드 / BGM 방향
- **BGM**: 어쿠스틱 기타 + 우쿨렐레 + 글로켄슈필, **루프 가능한 칠 BGM**
  - 템포: 80~100 BPM
- **SFX**:
  - 드롭: 가벼운 "톡" / "퐁"
  - 머지: 등급별로 음정이 약간씩 높아지는 "팅~" (음악적 페어링)
  - 수박 완성: 풍성한 합창/벨 효과
  - 게임 오버: 부드럽게 페이드 + 짧은 아련한 멜로디
- **오디오 톤**: 짜증나지 않게 — 반복 청취 가능한 부드러움

### 6.5 햅틱 (모바일)
- 드롭: 미세 진동
- 머지: 단계 비례 진동 (수박은 더블 펄스)

## 7. 기술 노트 (Implementation Notes — Unity 6.3)

> 이후 구현 의뢰 시 본 GDD와 함께 참고할 기술 가이드라인.

### 7.1 권장 구조
- **Fruit (Prefab)**: `Rigidbody2D`, `CircleCollider2D`, `SpriteRenderer`, `Fruit.cs`
- **FruitData (ScriptableObject)**: level, sprite, radius, score, prefab 참조
- **Spawner**: 다음 과일 큐, 가중치 랜덤
- **MergeManager**: 충돌 이벤트 수집, 머지 큐 처리, 중복 머지 방지(락)
- **GameManager**: 상태(타이틀/인게임/오버), 점수, 데드라인 판정 타이머
- **UIManager**: HUD, 결과창
- **AudioManager**: 머지 음정 단계별 재생

### 7.2 핵심 주의사항
- **머지 중복 방지**: 충돌 콜백에서 `isMerging` 플래그 또는 `instanceID` 비교로 동일 페어가 양쪽에서 트리거되는 것 차단
- **물리 안정성**:
  - `Rigidbody2D.Sleep Threshold` 조정
  - `Physics2D.velocityIterations`, `positionIterations` 적절히 (기본값 우선)
  - 콜라이더 반지름과 스프라이트가 정확히 일치하도록 (시각/물리 mismatch 방지)
- **데드라인 판정**: `Trigger Collider` 라인 + 진입 시간 누적
- **드롭 락**: 머지 큐가 비기 전엔 새 드롭 허용해도 무방하지만, 시각적 혼란 방지 위해 0.5초 쿨다운

### 7.3 데이터 저장
- `PlayerPrefs`: 하이스코어, 옵션 (볼륨 등)
- 옵션: 추후 JSON/스크립터블 오브젝트로 확장

## 9. 용어집 (Glossary)

- **머지(Merge)**: 같은 등급 과일 두 개가 결합해 한 단계 위 과일이 되는 행위
- **데드라인(Death Line)**: 게임 오버를 판정하는 상단 기준선
- **체인(Chain)**: 한 번의 머지가 다른 머지를 즉시 유발하는 연쇄
- **드롭 슬롯(Drop Slot)**: 화면 상단의 과일 조준 영역
- **티어(Tier) / 레벨(Level)**: 과일의 등급 (1=체리 ~ 11=수박)
